# dsh-memory

给 DeepSeek Harness 用的**跨对话长期记忆**插件：数据存本机 SQLite，新会话自动接上旧进度，全部离线。

> 这是一个面向特定 Harness 版本（0.2.1-rc.3）的桌面插件，不是通用 npm 包。

## 它解决什么

- 上下文用完后，新开的对话能直接接上旧对话的结论和待办
- 偏好、决定、项目背景不会因为换窗口而丢失
- 记忆按项目隔离：数据库路径、实现决定只属于对应项目；"用中文交流"这类偏好才是全局的

## 功能

| 能力 | 说明 |
|---|---|
| 每对话一个库 | `年_月_日_时_分.db`，WAL 模式，单独文件、单独大小 |
| 事实与偏好 | 带类别、重要度、常驻标记；访问后强度提升，闲置衰减 |
| 交接 | 记录"覆盖到第几条消息"，缺口超过 12 条提醒一次 |
| 检索 | 中文安全的分词匹配，跨全部对话库，不受单库条数上限影响 |
| 自动注入 | 提示里插入常驻记忆、项目相关事实、最近交接 |
| 项目作用域 | 默认只读「当前项目 + global」，未分类记忆需显式查询 |
| 设置页 | 每个库的条数、大小、占比、路径；容量提醒；归档折叠 |
| 安全迁移 | 统一准入、一致副本、持久日志、崩溃后恢复 |

## 安装

需要 Node 22+（插件用 `node:sqlite`）和 DSH 0.2.1-rc.3（Windows 验证）。

```bash
git clone https://github.com/Elysia-Eden-A/dsh-memory-s.git
cd dsh-memory-s
node scripts/install.mjs
```

脚本会把仓库链接进 DSH profile（`@local/dsh-memory`）、登记到 `dsh.profile.bundles`，并校验四个模块都能解析。然后完全退出并重开 DSH，打开 **设置 → 记忆存储** 确认页面。

详细步骤、手动装法、卸载和排查见 [INSTALL.md](INSTALL.md)。

数据默认在插件目录下的 `data/`，可在设置页迁移到别处。

```

scripts/install.mjs 安装脚本（profile 链接、登记、校验）
test-migrate.mjs    迁移核心的 5 个场景
test-coordinator.mjs 协调器的 4 个场景
```

## 迁移的设计要点

这里花了最多时间，因为它出错会丢数据：

- **一致副本**：用 `VACUUM INTO` 生成，不是复制文件（WAL 和进行中的事务会让复制结果不一致）
- **显式切换**：`copying → prepared → 指针 → committed → done`，日志落盘
- **恢复优先**：启动时先读日志和实际指针，再决定哪边是权威数据
- **访问协调**：迁移期间统一准入；排空超时取消迁移；暂停期消息进持久队列，按 `(session, seq)` 幂等补写
- **校验完整**：索引关键表 + 每个会话库文件存在 + 每个库有 `messages` 表；缺一项就保持关闭并报错，不创建空库掩盖问题

## 测试

```bash
node test-migrate.mjs      # 迁移核心
node test-coordinator.mjs  # 准入与队列
```

宿主层的四项验收（长任务等待、迁移期消息、超时回源、目标接管）是在独立 Harness 实例里用真实 HTTP 和真实会话事件跑的，结果记录在项目维护者的验收清单里。

## 已知边界

- 作用域用工作目录路径表示：移动目录会换作用域，同一目录下多个项目共享作用域
- 未覆盖：同步任务在途与迁移的竞争、多窗口并发、真实磁盘故障、跨工作区续接的完整链路
- 只验证过 Windows + Node 26 的 `node:sqlite`
